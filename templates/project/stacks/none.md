# Framework-independent guidance

Guidance profile: none. This does not mean the project has no technology stack.

- Observe actual source, manifests, build configuration, documentation, and tests
  before recording languages, frameworks, versions, or runtime targets.
- Work with empty, documentation-only, mixed-stack, and non-Git projects too.
  Record unavailable or inapplicable evidence explicitly.
- Preserve established architecture, interfaces, dependencies, and conventions.
  Do not invent packages, commands, tests, business purpose, runtime defaults,
  performance measurements, workload assumptions, or framework requirements.
- Separate observations and assumptions from accepted decisions. Example
  environment values are examples until runtime configuration establishes them.
- Follow engineering, workflow, and bootstrap guidance. Preserve validation,
  security, accessibility, error handling, compatibility, and data integrity.
- Run only authorized checks supported by inspected project configuration;
  explain practical manual verification without launching applications.
